Python library: column expressions with nullable Arrow semantics.

The Simjit Python library has native support for {{ project_link(project_links.numpy, "NumPy") }} and {{ project_link(project_links.pyarrow, "PyArrow") }} arrays, and can also accept objects exposing the {{ project_link(project_links.python_buffer, "Python buffer API") }}. It operates directly over provided buffer memory.

Nullable Arrow support is part of the expression semantics: filters, projections, and aggregations can handle nulls through the validity bitmap, without separate null-checking code.

Pointer-based expression calls

Simjit takes typed input and output arrays as pointers, so an engine can keep its own chunks, vectors, validity buffers, and aggregation state.

The API describes the expression as a dataflow; the surrounding vectorized processing system owns the data layout and decides where to call the compiled function.

DuckDB proof of concept: A vectorized engine can hand expression fragments to Simjit.

DuckDB still handles scanning, chunking, and aggregation state; Simjit replaces selected expression-fragment evaluation.

Scope and positioning: A compact compiler for vectorized expression evaluation.

Unlike Hyper and Umbra, which compile whole query plans, Simjit compiles individual expression fragments: a filter, a projection, or an aggregate expression. The surrounding engine keeps its planner, storage, and scheduler.
