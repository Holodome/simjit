# Simjit Fuzzing

Run fuzz commands from the repository root.

## Layout

- `fuzz/simjit-fuzz`: unified driver for transforming fuzz artifacts.
- `fuzz/render-html.py`: outcome JSON to grouped HTML report renderer.
- `fuzz/fuzz_common.py`: shared driver implementation helpers.
- `fuzz/simjit-xsmith.rkt`: Xsmith generator.
- `fuzz/simjit_fuzz_tool.cpp`: C++ helper built by `make fuzz-tools`.
- `fuzz/simjit_lisp_format.py`: serializer formatting helpers used by reports.

Generated outputs belong under `test-dump/`. Racket may create
`fuzz/compiled/`; it is generated bytecode and is ignored.

## Prerequisites

```sh
make fuzz-tools
raco pkg install xsmith
```

## Artifact Kinds

- `program`: one serialized `.simjit` function.
- `corpus`: JSONL with generated programs.
- `bundle`: JSONL with compiled code blobs.
- `outcome`: one JSON object with run results.

## Core Driver

```sh
fuzz/simjit-fuzz \
  [--from program|corpus|bundle] \
  --to program|corpus|bundle|outcome \
  [--input PATH|-] \
  [--output PATH|-]
```

- `--to` is always required.
- Use `--from` only when an input artifact already exists.
- Omit both `--from` and `--input` to generate from nothing.
- `-` means stdin or stdout.

Generate one program:

```sh
fuzz/simjit-fuzz --to program --seed 4
```

Generate a corpus:

```sh
fuzz/simjit-fuzz --to corpus --seed 100 --count 10 --output /tmp/corpus.jsonl
```

Canonicalize and format one program:

```sh
fuzz/simjit-fuzz \
  --from program \
  --input /tmp/one.simjit \
  --to program \
  --format \
  --output /tmp/one.pretty.simjit
```

Minimize one program to selected roots:

```sh
fuzz/simjit-fuzz \
  --from program \
  --input /tmp/one.simjit \
  --to program \
  --minimize-roots 12 \
  --output /tmp/one.min.simjit
```

Validate a corpus:

```sh
fuzz/simjit-fuzz \
  --from corpus \
  --input /tmp/corpus.jsonl \
  --to corpus \
  --validate syntax
```

Compile a corpus into a bundle:

```sh
fuzz/simjit-fuzz \
  --from corpus \
  --input /tmp/corpus.jsonl \
  --to bundle \
  --preset scalar-diff \
  --output /tmp/tests.jsonl
```

Run a bundle:

```sh
fuzz/simjit-fuzz \
  --from bundle \
  --input /tmp/tests.jsonl \
  --to outcome \
  --output /tmp/outcome.json
```

Generate, compile, and run in one step:

```sh
fuzz/simjit-fuzz \
  --to outcome \
  --seed 100 \
  --count 10 \
  --preset vector-observe \
  --output /tmp/outcome.json
```

## Reports

Render an existing outcome:

```sh
fuzz/render-html.py /tmp/outcome.json --output /tmp/outcome.html
```

## Stage Flags

Generation:

- `--seed`
- `--count`
- `--start-index`
- `--profile`
- `--max-depth`
- `--batch-size`
- `--jobs`

Compile:

- `--preset {syntax,builder-validate,compile-validate,compile-observe,scalar-diff,vector-observe,vector-strict}`
- `--arch {native,x86,arm}`
- `--cpp` to include C++ backend blobs in generated bundles
- `--jobs`
- `--wait-for-debugger`

Program and corpus utilities:

- `--format`
- `--minimize-roots 1,2,...`
- `--validate {syntax,builder}`

Artifacts:

- `--artifacts-dir PATH`
- `--clear-artifacts`

## Cross-Arch Workflow

Build a strict compile-only bundle for another architecture:

```sh
fuzz/simjit-fuzz \
  --from corpus \
  --input /tmp/corpus.jsonl \
  --to bundle \
  --preset compile-validate \
  --arch x86 \
  --output /tmp/tests-x86.jsonl
```

Then copy that bundle to an x86 machine and run:

```sh
fuzz/simjit-fuzz \
  --from bundle \
  --input /path/to/tests-x86.jsonl \
  --to outcome \
  --output /path/to/outcome.json
```

The driver records the concrete target arch in bundle items and refuses to run a
foreign-arch bundle locally.

`compile-validate` is the compile-only preset for this workflow. It requires:

- syntax to be valid
- deserialize and `FunctionBuilder::build()` to succeed
- scalar codegen to succeed
- vector codegen to succeed when the function is not marked scalar-only

It does not run the generated code.

Use `compile-observe` when you want scalar-success items in the output bundle
even if vector codegen fails. Vector failures are saved into artifact buckets
when `--artifacts-dir` is set.

## Outcome Format

Top-level fields:

- `kind: "outcome"`
- `summary`
- `items`

`summary` includes:

- `total`
- `passed`
- `syntax_fail`
- `builder_fail`
- `scalar_fail`
- `vector_fail`
- `mismatch`
- `preset`
- `arch`

Each `items[]` entry includes:

- `id`
- `program_index`
- `program_seed`
- `profile`
- `preset`
- `arch`
- `serialized`
- `hir_scalar_only`
- `scalar_status`
- `vector_status`
- `status`
- `errors`
- optional `comparison` for mismatches

## Artifact Buckets

If `--artifacts-dir` is set, non-pass cases are written into:

- `syntax-fail`
- `builder-fail`
- `scalar-fail`
- `vector-fail`
- `mismatch`
- `runtime-crashes`

Each saved non-crash case includes:

- `<bucket>/seed-...-idx-....simjit`
- `<bucket>/seed-...-idx-....json`
